# Design System Foundations

- Use a warm woodland RPG identity: forest-green navigation, parchment content in light mode, moss content in night mode, and light wood primary actions. Keep Marten and the existing scenes, fonts, and icons. Vermilion is not part of the approved palette.
- Every timer state has text and accessible controls; color/audio/animation never carries state alone.
- Support keyboard navigation, visible focus, 320px web layout and reduced motion.
- Reserve visual density for Return Card and active session; Circle/forest surfaces remain calm and secondary.
- Build responsive components with mobile information hierarchy so future native UI can share semantic states, not CSS.

## Light and night themes

Semantic tokens live in `apps/web/src/shared/styles/renovation.css`. Shared surfaces use #EDF0E4 paper, #F7F4E9 parchment, and #E5E9D9 wash in light mode; night uses #13281F paper, #20392C moss, and #2B4736 wash. Primary actions use #E1B77B wood with #302318 text in both themes; #93663D edges and shallow #775332 depth distinguish them from secondary controls. Accent and foreground-on-accent remain separate for selected choices. Forest navigation retains cream text on dark green. Theme follows the device with browser-local overrides applied before React renders. No backend profile preference is implied.

The signed-in working area shares the landing section edges: up to 1600px of content inside an outer 1664px box with 32px desktop gutters. Tablet gutters are 24px and mobile gutters 16px; related columns are separated by 24px. The five primary destinations are Return, Dashboard, Camp, Pacts, and Memory. They occupy the forest top bar from 1200px, a second top-bar row from 760px to 1199px, and the measured bottom navigation below 760px. Settings is available through the two-item Account dropdown with Sign out; it is not a primary navigation tab. The Account dropdown stays attached to its trigger and does not lock scrolling. The browser-local theme choice remains in Settings, while scene atmosphere controls remain in their existing locations. Camp shares the top bar and keeps its contextual back action below it. Focus remains immersive with its compact tools. Landing's public header/footer retain their own centered canvas.

Split related content when the available content container reaches 800px, rather than using viewport width alone. Return puts the start/resume flow on the left and upcoming appointments plus a quiet Dashboard link on the right; the study statistics live only in Dashboard. Camps use up to three cards per row; Pacts use two, then three when space allows. Pact detail uses 60/40. Personal and shared memory pair the preview/editor with milestones and history (40/60). Settings use two columns with independently expandable sections; profile and preferences begin open. Mobile uses the same mounted components in reading order, preserving drafts through resize.

Solo and shared Focus use the same 1600px content cap while their forest scenes remain full-viewport backgrounds. Camp detail uses a centered 1600px cap for its bounded scene and controls.

Dashboard shows self-reported Solo study steps and the account's closed Solo/Camp sessions for 7 or 30 local calendar days. Daily bars, status totals, and adjacent equal-length period comparisons have written values and a daily table; they do not imply streaks, scores, or unrecorded completion. The recent-step editor and unrecorded Solo-session actions moved from Return to Dashboard. Data remains private to the signed-in account.

Solo and shared Focus use document flow: intention on the left, timer and actions grouped together on the right, with an 864px outer-container threshold that allows for gutters. Ending and checkout forms split related fields when there is room. Solo tools are up to 720px wide; Camp panels and checkout are up to 880px. Camp retains its interactive scene in a bounded panel beside its actions, with information/actions before the scene on mobile. The landing hero pairs its introduction with one instance of the existing interactive preview. Forest scenery supports the content and never reserves an empty column. Long reading copy stays around 65ch, simple forms around 640px, auth at 480px, and invite confirmation at 720px.

Use spacing and surface tone before borders. Keep separators for meaningful list/table boundaries and input outlines. Shape tokens are `--radius-control:12px`, `--radius-panel:16px`, and `--radius-dialog:20px`; mobile sheets retain their full-bleed lower edge. Primary buttons have 3px depth and press down 2px; secondary actions remain quieter. Navigation and selected choices use a whole outline and background, not a bottom or side stripe. Buttons, action links, and navigation never use underlines in any state; ordinary links inside prose retain their link affordance.

Text-heavy areas group a heading, nearby explanation, controls, feedback, and action in that order. Independent groups may use a light wash and thin border; related rows use a divider or spacing instead of nested panels. Return separates start help, optional AI context, the request, and its result. Dashboard separates recent steps from the next step. Camp, Pact, Memory, Focus ending, and Settings follow the same hierarchy while preserving one obvious primary action in each decision area.

Disclosure summaries provide at least a 44px target, a single clear indicator, visible focus, and distinguishable open and closed surfaces. Native `<details>` keep keyboard activation; React-managed initial state must preserve the user's later open/close choice across rerenders. The Return appointment list starts closed when empty and open when it contains appointments. Buttons that reveal panels expose their current expanded state and panel relationship. Escape closes menus and returns focus to the trigger. Reduced motion removes indicator and panel motion.

SVN-Engine remains on prominent display headings, Be Vietnam Pro on navigation and body text. Touch targets are at least 44px. Control feedback takes 160ms and panel entry/exit 200ms with a small translation; reduced motion removes translations and animations. Disabled/loading actions do not lift or depress. Focus sessions keep their existing scene behavior without adding looping interface animation, scores, quests, or interaction sounds. Timer, server state, privacy, and data contracts are unchanged.

See [delivery contract](ui-renovation-delivery.md) for state/API boundaries and validation evidence.

Memory summaries belong in the Memory tab. Return keeps study progress and upcoming appointments; Camp keeps its operational controls. Neither screen renders a personal/shared milestone summary, preview card, or memory-summary loading/error/retry UI. Scene growth, access revalidation, and the existing Focus ending notice retain their behavior.
